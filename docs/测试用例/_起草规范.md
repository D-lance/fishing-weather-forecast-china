# 测试用例起草规范（钓鱼天气预报项目）

> 起草前先读本文件 + `.claude/rules/API_WebPage_TestCase.md`。
> 本项目没有后端 / 数据库 / 登录 / 多租户 / 软删除；不要套用这些概念。

## 1. 产出物与位置

| 类型 | 路径 | 编号 |
|---|---|---|
| 模块用例 | `docs/测试用例/<模块>-验收用例.md` | `TC-<MOD>-<N/A>-<序号>` |
| 页面用例 | 同上 | `TC-<MOD>-UI-<N/A>-<序号>` |
| 链路用例（可选） | `docs/测试用例/链路用例/C<NN>-<名称>.md` | `C<NN>-<步骤>` |

模块缩写示例：首页 `HOME`、搜索 `SRCH`、地图 `MAP`、评分 `SCORE`、详情 `DETAIL`、双语 `I18N`、分享 `SHARE`、数据 `DATA`。

## 2. 必须遵守的硬性约定

1. **接口用真实路径**：从 `web/engine.js` 的 `forecastUrl` / `marineUrl` / `geocodeUrl` / `overpassQuery` 读；禁止臆造接口。
2. **外部接口只看 HTTP 200 + JSON 结构**：没有 `code=1`、Token、分页 `page/limit`、软删除、数据库断言。
3. **引擎用例用 `computeForecast`**：合成 Open-Meteo 响应；优先复用 `tools/test-engine.mjs` 的造数方式。
4. **每条用例必须有执行方式**：浏览器 / Node 引擎测试 / 外部 API 探针 / 代码审查。
5. **每条用例必须有执行结果**：✅ 通过（注明方式）/ ❌ 不通过（当场修到通过）/ ⚠️ 不可演示（注明原因）。
6. **不编造测试数据**：用已知水体（太湖、千岛湖、汉江、象山港）或合成响应；不提交真实个人位置、鱼获数据。
7. **模型红线必须覆盖**：
   - 安全封顶：雷暴 / 7 级阵风 / 2.5m 浪 / 强降水；
   - 热季最后一天 23 个参与小时（04–23 + 次日 00–02）；
   - 分数/分项/时段在 0–100、无 NaN；
   - 英文输出无中文残留。
8. **频率与礼貌**：Nominatim ≤1 次/秒；Overpass 按 `OVERPASS_MIRRORS` 顺序切换；不要压测公共接口。
9. **浏览器用例必须看 Console 和 Network**：无 error/warning、无 5xx、无无限 loading。
10. **涉及地图的用例必须包含失败路径**：Leaflet CDN 超时/被拦截时，选点流程不能永久卡死。
